Curso 00 · meta

Cómo funciona esta escuela

Las reglas del juego, la estructura de los cursos y cómo crecerá este laboratorio junto con el template.

El objetivo

Construir un template Flutter reutilizable cuya primera aplicación real será la versión móvil del ERP Gibbor (hoy en React Router v8). Cada decisión del template se estudia en un mini-curso antes o mientras se implementa, siempre traduciendo desde lo que ya conoces de React.

Las reglas del juego

  • Erik escribe el código. Claude solo modifica archivos cuando se le pide explícitamente.
  • Cada consulta puede volverse un curso. Si la respuesta merece quedar documentada, se crea su página y se registra en el índice.
  • Todo se traduce desde React. Los cursos usan comparaciones lado a lado: cómo lo harías en Gibbor, cómo se hace en Flutter.
  • El código real manda. Los ejemplos citan archivos reales de lib/, no código de juguete.
  • Nada queda mal hecho. Todo lo que se escribe es production-grade; un tema puede empezar simple, pero se lleva hasta el nivel producción antes de cerrarse.

Andamiaje: tres niveles

El acompañamiento baja de intensidad conforme Erik recupera el músculo de Flutter (liberación gradual de responsabilidad). En cualquier momento, cualquiera de los dos puede pedir subir o bajar de nivel — y un tema nuevo difícil puede volver al nivel 1 aunque el resto del proyecto vaya en el 3.

  • Nivel 1 · Código completo (cursos ~01–03): Claude muestra el código anotado; Erik lo teclea (nunca copy-paste) y explica una línea a elección de Claude. Antes de mostrar, una predicción: "¿qué crees que va aquí?".
  • Nivel 2 · Hints (~04–07): firmas, estructura y pistas; Erik rellena. Se llega aquí cuando escribe providers/notifiers sin mirar referencia.
  • Nivel 3 · Solo (~08–11): Erik escribe; Claude hace code review después. Se llega aquí cuando las soluciones vuelven sin correcciones estructurales.

Anatomía de un curso

Cada curso es un HTML independiente creado a partir de _plantilla-curso.html. Todos comparten assets/base.css, así que el estilo es consistente sin repetir nada. Los bloques disponibles:

React (Gibbor) 
// Así se ven las comparaciones:
// izquierda, lo que ya dominas
export async function loader() {
  return getProducts();
}
Flutter (mini_flutter) 
// derecha, su equivalente Flutter
final productsProvider =
  FutureProvider((ref) =>
    ref.read(apiProvider).getProducts());
★ Insight. Así se ven las notas clave: la idea que conecta el detalle técnico con el panorama general del template.

Las demos son interactivas

Cuando un concepto lo amerite, el curso incluye demos con SVG, canvas, GSAP o three.js. Esta usa el concepto más famoso de Flutter — la UI es una función del estado — sin ninguna librería:

demo · UI = f(estado)

estado actual: contador = 0

0

El botón no toca la caja: solo cambia el estado. La "caja-widget" se reconstruye sola a partir de él — igual que un rebuild de Flutter o un re-render de React.

Cómo se agrega un curso

  1. Copiar _plantilla-curso.html → curso-NN-tema.html.
  2. Registrarlo en el array CURSOS de index.html:
docs/html/index.html 
const CURSOS = [
  // ...
  {
    num: "01",
    titulo: "Título del curso",
    desc: "Qué responde este curso, en una frase.",
    href: "curso-01-tema.html",
    estado: "en-curso", // pendiente | en-curso | completado
  },
];
